# Teya — бриф сайта (`/teya-brief`)

Команда для **Директора / сайтостроителя**. Язык общения с пользователем — русский, без английского жаргона в сообщениях пользователю.

## Цель

Когда пользователь просит бриф на сайт (или сайтостроитель начинает новый сайт):

1. **Сразу отправь пользователю пустой заполняемый бриф** — содержимое `shared/site-brief-template.md` (или копию из чата).
2. **Дождись заполненного брифа** в чате (текст и/или вложения: логотип, референсы, скрины).
3. Только после этого **перенеси данные** в память проекта и запускай пайплайн.

Не начинай research / AURA / сборку страниц, пока нет заполненного брифа (или явного ответа на недостающие обязательные поля).

## Обязательные ручные поля (пользователь настаивает)

Из заполненного брифа **обязаны** быть (если пусто — спроси в чате, не выдумывай):

| Поле | Правило |
|------|---------|
| **Число страниц + список страниц** | Если в брифе N страниц (список) — строй **ровно N**. Старый потолок «максимум 5 страниц» **не применяется**, когда бриф задаёт набор страниц. Если числа/списка нет — спроси; не подставляй дефолт «5». |
| **Число статей блога** | Бери число из брифа. Темы — из брифа; недостающие темы можно предложить **в пределах указанного числа**, не раздувая count. Если блог «не нужен» — не планируй статьи Phase 1. |
| **Ключевые слова** | Только из брифа или явного ответа в чате («вот ключи» / «подобрать вместе»). **Не** вызывать Ядрышко / Wordstat / MCP-KV для расширения. Лёгкая нормализация slug допустима. |
| **Как должен выглядеть сайт + примеры** | Описание стиля, must-keep/must-avoid, ссылки и присланные изображения — в `site.inv` / `00-brief.md` без потери. |

Служебные страницы «Политика конфиденциальности» и «Политика cookies» (+ cookie banner) Teya добавляет по контракту всегда; их **не** надо вычитать из пользовательского N, если пользователь не включил их в свой список как отдельные контент-страницы.

## Алгоритм сайтостроителя / Директора

### Шаг A — выдать шаблон

1. Прочитай `teya/shared/site-brief-template.md`.
2. Отправь пользователю **полный пустой шаблон** в чат (можно сказать: «Заполните бриф ниже и пришлите ответом»).
3. Не проси править файлы на диске руками.

### Шаг B — принять заполненный бриф

1. Сохрани сырой текст пользователя в `teya-memory/00-brief.md` (с пометкой источника: чат / файл).
2. Если не хватает обязательных полей из таблицы выше — короткий список уточнений в чате, затем допиши `00-brief.md`.

### Шаг C — перенос в анкету и семантику

Сам (пользователь файлы не редактирует):

1. Заполни `teya-memory/site.inv` из брифа (`rules/manual-keywords.mdc`).
   - `niche`, `services`, контакты, geo, design reference / style_notes / visual_must_keep.
   - `starter_blog_posts` = число статей из брифа (или 0, если блог не нужен).
   - Добавь/обнови понятные поля в `[content]`, например: `pages_count`, `pages_list` (краткий список названий/slug), `blog_articles_count`.
2. Построй manual keywords + URL map по skill `manual-keywords-url-map`:
   - `04-keywords-clean.csv` — **только** ключи из брифа / ответа в чате;
   - `06-url-map.csv` — **все** страницы из списка брифа (главная + перечисленные); slug можно слегка нормализовать (`Услуги` → `/uslugi`);
   - `11-blog-topics.md` — ровно `blog_articles_count` тем (из брифа или дополненные до числа, но не больше);
   - fragment `=== KEYWORDS + URL MAP (MANUAL) ===`.
3. **Запрещено:** придумывать число страниц, число статей или ключи сверх брифа; обрезать список страниц брифа до 5 «для теста».

### Шаг D — старт работ

После `00-brief.md` + `site.inv` + (при наличии ключей) manual map — продолжай `/teya-phase1` / skill `director-teya`.

Маркер в handoff: `=== BRIEF (ВХОД) ===` со статусом ✅ и явным `pages_from_brief: N`, `articles_from_brief: M`.

## Связь с другими командами

- `/teya-start` — общий первый контакт; при запросе брифа предпочитай этот `/teya-brief` (шаблон целиком).
- `/teya-new-site` — сначала reset памяти, затем снова `/teya-brief`.
- Ядрышко / Wordstat — **не** использовать.
- Общий шаблон внутренних страниц (`shared-inner-page-template`) — **сохраняется**: N страниц брифа = N контент-вариантов на одном `inner-shared`, уникальная — главная (или страница с `unique_template_reason`).

## Сообщение пользователю (пример тона)

«Пришлите заполненный бриф по шаблону ниже: сколько страниц и какие, сколько статей, ключевые слова, как должен выглядеть сайт и примеры. Как только бриф будет у меня — перенесу всё в работу и начну сборку.»
